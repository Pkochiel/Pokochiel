# /process-inbox（最小版 v0.1）

## 絶対条件

**このコマンドは読み取り専用である。**
ファイルの作成・変更・移動・削除・リネームを一切行わない。
出力はレポート（提案）のみ。実行は人間の承認後に別途行う。

ユーザーから「ついでに作っておいて」と言われた場合も、
このコマンド内では実行せず、承認を得たうえで通常の作業として行うこと。

## 実行手順

1. `CLAUDE.md` を読む
2. `80_System/workflows/process-inbox.md` を読み、**その仕様に厳密に従う**
3. `80_System/tag-taxonomy.md` / `metadata-schema.md` / `naming-convention.md` を読む
4. `00_Inbox/**/*.md` を Glob で列挙し、各ファイルを Read
   - 引数 $ARGUMENTS でファイル名やフォルダが指定されていれば、その範囲に限定する
5. 各アイテムを分類・要約する（**元の情報にないことを書き足さない**）
6. Atomic Note 候補を抽出する（候補ゼロも正当な結論）
7. **候補ごとに Vault 全体を Grep / Glob で検索し、重複判定する（省略禁止）**
   - ファイル名の類似、本文中の概念語、英日両表記、`aliases` を確認
   - 判定は `新規` / `類似あり` / `重複` の3値
8. `tag-taxonomy.md` の語彙内でタグを提案する（語彙外は「追加提案」として別記）
9. WikiLink 候補を、**関連理由つきで**提案する
10. 影響する MOC と、追加すべき具体的な行を提示する
11. `80_System/workflows/process-inbox.md` の出力フォーマットでレポートを出す

## 注意

- `00_Inbox/` が空なら「処理不要」と報告して終える。無理に何かを作らない
- 秘密情報（APIキー・トークン・認証情報）を検出したら、
  **内容をレポートに転記せず**、該当ファイル名と警告のみを報告する
- クライアント固有の機微情報は、匿名化を提案する
- 判断に迷うものは `fragment` として残置を提案し、
  「何が足りなくて判断できないか」を明記する
- レポートの最後に必ず「承認後に実行すること」を番号付きで列挙する
