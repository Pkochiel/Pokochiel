# スポスタ（Spot Stamp）

お気に入りのスポット（温泉・グルメ・カフェ・観光・自然…）を地図にピン留めしてグループで共有し、
「行った！」でスタンプを集めるスタンプラリー Web アプリです。スマホを片手で操作できるように作っています。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| オープニング | ピンが降ってきて「旅」の判子がドンッと押されるアニメーション（タップでスキップ、`prefers-reduced-motion` に対応） |
| 地図 | Leaflet と OpenStreetMap のタイルを使用（国内も海外もOK）。カテゴリで絞り込み、現在地表示、全スポット表示 |
| スポット登録 | 名称、カテゴリ、場所、コメント、写真。場所は地図を動かして📍を合わせるか、地名検索（Nominatim）か、現在地で指定。住所は自動入力 |
| スポットカード | ピンをタップすると写真と詳細のカードが下から出る。ルート案内、共有、編集・削除（登録した本人のみ） |
| スタンプ | 「行った！」を押すとハンコが落ちてきて押印され、画面が揺れて、振動と効果音、紙吹雪が出る。500m以内で押すと「現地認定」の金メダルが付く |
| マイ・スタンプ帳 | 獲得したスタンプと未獲得の空き枠（近い順）、称号ランク、次の称号までのゲージ、コンプ率、カテゴリ別の達成状況、バッジ15種、「次はここ！」 |
| グループ | 招待リンク／コードでグループを作成・参加。メンバーのランキング、誰が行ったかの表示 |

## 起動

```bash
cd spot-stamp
npm install
npm run dev        # API(8787) + Vite(5173)。スマホからは http://<PCのIP>:5173
```

本番:

```bash
npm run build
PORT=8787 DATA_DIR=./data npm start   # dist/ と API を1プロセスで配信
```

環境変数: `PORT`, `DATA_DIR`（JSON と写真の保存先）, `VITE_TILE_URL` / `VITE_TILE_ATTRIBUTION`（地図タイルの差し替え用。Mapbox などに変える場合）, `VITE_API_BASE`。

## データの信頼性まわり

- **端末に先に保存する方式**: すべての操作はまず端末（localStorage、写真は IndexedDB）に保存し、送信キューから順番にサーバーへ送ります。オフラインや移動中で電波が途切れてもデータは失われず、つながったら自動で再送します（指数バックオフ、`online` イベント、画面復帰時）。
- **押印の保存**: 端末への保存に失敗したとき（容量不足やプライベートモード）は押印を取り消してエラーを表示します。押したように見えて実は保存されていない、という状態は起きません。二重タップしてもスタンプは1つです。
- **冪等なAPI**: スポットの ID はクライアント側で生成し、PUT で登録・更新します。再送しても重複しません。古い更新が後から届いた場合は無視します（Last-Write-Wins）。
- **競合の扱い**: 削除済みスポットには墓標を残し、410 を返します。他人のスポットの編集・削除は 403 です。再送しても成功しない 4xx はキューから外して画面に通知します。
- **サーバー側の保存**: ルームごとに書き込みを直列化し、一時ファイルに書いてから rename するので、書き込み中に落ちてもファイルが壊れません。壊れたファイルは消さずに退避します。
- **入力検証**: クライアントとサーバーの両方で行います。写真はマジックバイトで中身を確認し、パストラバーサルも防いでいます。localStorage が一部壊れていても、読める部分は復元します。
- 画面の描画エラーは ErrorBoundary で受け止め、真っ白な画面になるのを防ぎます。複数タブで開いている場合も `storage` イベントで状態を揃えます。
