# Tag Taxonomy（統制語彙）

> [!warning] 最重要ルール
> **このファイルに定義されていないタグを使ってはならない。**
> Claude Code はタグを独断で新設しない。必要なら「このタグを追加すべき」と
> 提案し、人間が承認して本ファイルに追記してから使う。

タグ乱立は Knowledge OS を壊す最大の要因である。
初期語彙は**意図的に少なく**してある。増やすのは、実際に困ってからでよい。

## 使い方のルール

- 1ノートあたり **3〜5個まで**
- タグが表すのは **領域・テーマだけ**。`type` と `status` は frontmatter の
  役割であり、タグで二重管理しない（`#atomic` `#raw` などは禁止）
- 階層は1段まで（`ai/llm` は可、`ai/llm/rag/eval` は不可）
- 単数形・小文字・英語で統一（`ai` であって `AI` `ais` ではない）

## 語彙

### ドメイン（領域）

| タグ | 意味 |
| --- | --- |
| `ai` | AI 全般 |
| `ai/llm` | 大規模言語モデル |
| `ai/agent` | エージェント・自動化 |
| `consulting` | コンサルティングの実務・技法 |
| `strategy` | 経営戦略・事業戦略 |
| `automotive` | 自動車業界 |
| `public-sector` | 公共・行政 |
| `technology` | 技術一般（AI 以外） |
| `productivity` | 生産性・仕事術・ナレッジ管理 |

### 知識の性質

| タグ | 意味 |
| --- | --- |
| `insight` | 自分の気づき・解釈。他人の主張の要約ではないもの |
| `hypothesis` | 仮説。未検証であることを示す |
| `research` | 調査結果・ファクト |
| `moc` | MOC ノート（`50_MOCs/` のノートに付ける） |

## 追加提案のしかた

新しいタグが必要だと感じたら、以下を満たすか確認してから提案する。

1. **既存タグ + WikiLink では表現できない**か
   → 表現できるなら追加しない
2. 今後 **5ノート以上**に付く見込みがあるか
   → 1〜2ノートにしか付かないものはタグではなく MOC かリンクで扱う
3. 既存タグと**意味が重なっていない**か

提案フォーマット:

```
提案タグ: ai/eval
理由: 評価・ベンチマーク関連が既に4ノートあり、ai/llm では粒度が粗い
影響: 既存ノート4件に追加付与を推奨
```
