# Workflow: `/process-inbox`（最小版 v0.1）

## スコープ宣言

**この最小版は、ファイルを移動しない・削除しない・上書きしない。**
出力は **レポート（提案）のみ**。人間が承認した項目だけを、別途実行する。

自動実行を最初から入れないのは、Vault の構造と分類基準が
まだ実データで検証されていないため。基準が固まってから自動化する
（`Structure before automation.`）。

## 目的

`00_Inbox/`（および指定があれば `05_Daily/` の未処理分）を読み、
`raw → processed / knowledge` への遷移候補を人間に提示する。

## 手順

### 1. 前提の読み込み
- `CLAUDE.md`
- `80_System/metadata-schema.md`, `tag-taxonomy.md`, `naming-convention.md`

### 2. Inbox の棚卸し
`00_Inbox/` 内の `.md` を列挙し、各ファイルについて記録する。
- ファイル名 / `created` / 本文の長さ
- 現在の `status`
- 滞留日数（今日 − `created`）

### 3. 分類
各アイテムを以下のいずれかに分類する。

| 分類 | 意味 | 行き先候補 |
| --- | --- | --- |
| `source` | 外部情報（記事・動画・資料） | `40_Sources/<media>/` |
| `insight` | 自分の気づき・主張 | `20_Knowledge/`（Atomic 化） |
| `framework` | 再利用可能な思考の型 | `30_Frameworks/` |
| `decision` | 意思決定の記録 | `60_Decisions/` |
| `project` | 特定案件の情報 | `10_Projects/<project>/` |
| `fragment` | 情報が足りず判断できない | `00_Inbox/` に残置（要追記） |
| `discard-candidate` | 価値が低い / 陳腐化 | **提案のみ。削除はしない** |

### 4. 要約
各アイテムを1〜3文で要約する。**推測で情報を補わない。**
元にない事実を書き足したら、それは捏造である。

### 5. Atomic Note 候補の抽出
「独立した1概念として切り出せるもの」を候補として列挙する。
候補ごとに以下を示す:
- 提案タイトル（`naming-convention.md` の主張形）
- Key Insight（1文）
- 根拠となる Inbox 上の箇所

**すべてを Atomic 化しようとしないこと。** 候補ゼロも正当な結論である。

### 6. 重複チェック（必須。省略禁止）
候補ごとに Vault 全体を検索する。
- Glob でファイル名の類似を確認
- Grep で概念語・同義語・英日両表記を本文検索
- `aliases` も検索対象に含める

結果を3値で報告する:
| 判定 | 意味 | 推奨アクション |
| --- | --- | --- |
| `新規` | 類似ノートなし | 新規作成 |
| `類似あり` | 関連ノートが存在 | 新規作成 + WikiLink、または既存へ追記 |
| `重複` | 実質同内容 | **新規作成しない。** 既存ノートへの追記を提案 |

### 7. タグ提案
`tag-taxonomy.md` の語彙内のみ。
語彙に無いものが必要なら、タグを付けずに「追加提案」として別記する。

### 8. WikiLink 提案
候補ノートごとに、張るべき既存ノートと**関連理由**を提示する。
理由を書けないリンクは提案しない。

### 9. MOC 更新提案
影響を受ける MOC と、追加すべきセクション・行を具体的に示す。
該当 MOC が未作成なら、その旨を報告する（勝手に作らない）。

### 10. レポート出力
下記フォーマットで出力して終了。**ファイル操作は一切行わない。**

## 出力フォーマット

```markdown
# Inbox 処理レポート — YYYY-MM-DD

## サマリ
- 対象: N件（うち滞留14日超: M件）
- Atomic Note 候補: N件（新規 N / 類似あり N / 重複 N）
- 要追記（判断不能）: N件

## アイテム別

### 1. `ファイル名.md`
- **分類**: source
- **要約**: 
- **提案先**: `40_Sources/web/2026-08-13 - Web - タイトル.md`
- **提案タグ**: `ai/llm`, `research`
- **Atomic 候補**:
  - 「提案タイトル」 — Key Insight: … / 重複判定: 新規
- **WikiLink 候補**: [[既存ノート]] — 理由
- **MOC**: `MOC - AI` の Core Concepts に追加

## 重複・統合の提案
（既存ノートへの追記で済むもの）

## タグ追加提案

## 判断を仰ぎたい点
（Claude が決めるべきでないもの）

## 承認後に実行すること
1. 
2. 
```

## Safety（このワークフロー固有）

- ファイルの**移動・削除・リネーム・上書きを行わない**
- `ai_generated: false` のノート本文を書き換えない
- Inbox に秘密情報を検出したら、**内容をレポートに転記せず**、
  「ファイル X に秘密情報の可能性」とだけ報告する
- 重複チェックを省略しない
- 空の Inbox は「処理不要」と報告して終える（無理に何かを作らない）
