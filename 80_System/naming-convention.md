# Naming Convention

## 原則

```
ファイル名 = frontmatter の title = WikiLink 表記
```

この3つが常に一致していること。ずれると WikiLink が壊れ、検索も効かなくなる。

## type 別ルール

| type | 形式 | 例 |
| --- | --- | --- |
| `atomic` | 概念を表す名詞句・命題。**日付を付けない** | `RAGは検索品質が上限を決める.md` |
| `framework` | フレームワーク名そのもの | `MECE.md` / `3C分析.md` |
| `source` | `YYYY-MM-DD - 媒体 - タイトル` | `2026-08-13 - YouTube - Agent設計の勘所.md` |
| `meeting` | `YYYY-MM-DD - 会議名` | `2026-08-13 - A社 定例.md` |
| `decision` | `YYYY-MM-DD - 決定事項` | `2026-08-13 - Vault構造をtype基準に統一.md` |
| `daily` | `YYYY-MM-DD` | `2026-08-13.md` |
| `moc` | `MOC - 領域名` | `MOC - AI.md` |
| `project` | フォルダ名 = プロジェクト名、中に `README.md` | `10_Projects/A社DX/README.md` |
| `inbox` | 自由。内容が推測できる語を含める | `メモ - Agent評価の論点.md` |

`媒体` は `YouTube` / `Web` / `PDF` / `書籍` / `社内資料` のいずれか。

## Atomic Note のタイトルの付け方

**良いタイトルは「主張」である。** 単語ではなく、言い切りの形にできるとよい。

| ❌ | ✅ |
| --- | --- |
| `RAG` | `RAGは検索品質が上限を決める` |
| `MECE について` | `MECEは網羅性より漏れの発見に価値がある` |
| `会議の話` | `合意形成の失敗は論点設定の段階で決まっている` |

単語だけのタイトルは「概念の器」になり、複数の主張が流れ込んで
Atomic でなくなる。ただし Framework と用語定義ノートは単語で構わない。

## 共通ルール

- **使用禁止文字**: `/ \ : # ^ [ ] |`（Obsidian の WikiLink が壊れる）
- 日本語・英語の混在は可。ただし**同じ概念に2つのノートを作らない**
  → 表記ゆれは `aliases` で吸収する（`metadata-schema.md` 参照）
- 連番プレフィックス（`01_`, `02_`）をノートに付けない。順序は MOC で表現する
- 拡張子は `.md` のみ
- ファイル名の先頭・末尾に空白を置かない

## 略語の扱い

- **一般的に定着した略語はそのまま使う**: `LLM` / `RAG` / `MECE` / `KPI`
- 定着していない略語は展開形をタイトルにし、略語を `aliases` に入れる
- 社内・案件固有の略語は、必ず展開形をタイトルにする（3ヶ月後に読めなくなる）

## リネームするとき

Obsidian 上でリネームすれば、WikiLink は自動追従する。
**Claude Code がファイルシステム経由でリネームする場合は自動追従しない**ため、
- リネーム対象への WikiLink を Grep で全件洗い出す
- frontmatter の `title` も同時に直す
- 参照元をすべて更新する

を1セットで行うこと。片手落ちは壊れたリンクを生む。
