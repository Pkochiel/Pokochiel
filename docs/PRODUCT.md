# Speed Reading Lab — Product Definition

## 1. コンセプト

**目を速く動かす訓練ではなく、読んだ内容を保っていられる力を鍛える。**

BTRメソッド（Basic Training for Readers）に沿って作る。
速読の中核はワーキングメモリであって、眼球運動の速さではない。
訓練は次の4段階を順に通す。

```
準備 → 認知視野の拡大 → 読書内容への集中 → 実際の読書
```

この4段階が、UX / Training Logic / Metrics のすべての設計判断の基準となる。
機能追加の是非は「どの段を鍛えるのか」で判断する。答えられない機能は入れない。

方法の詳細と、確認できたこと・推測でしかないことの区別は
[BTR_METHOD.md](BTR_METHOD.md) にまとめてある。

## 2. 提供しないもの（明示的な非目標）

科学的根拠が弱い、以下の能力を成果として謳わない。UI 文言・マーケティング文言でも使用しない。

- ページを写真のように丸暗記する
- 脳内音読（subvocalization）を完全に消す
- 一瞬見ただけで全文を記憶する
- 「1分で1冊」「10倍20倍」といった速度単体の誇張。目標は実用的な **3倍**

速度は指標のひとつに過ぎない。速度単体で最適化されるゲームにはしない。

## 3. ターゲットとユースケース

- 日本語のビジネス文書・技術文書・記事を日常的に大量に読む社会人
- 1日15〜90分を継続的に投下できる（その日取れる長さを選ぶ）
- Windows PC（腰を据えたトレーニング）と スマートフォン（隙間時間・翌日Recall）の双方で使う

## 4. 中心導線

```
ホーム → 長さを選ぶ（90 / 45 / 30 / 15 分）
  → カウント呼吸法 → 認知視野の種目 → 処理系の種目 → 普通読書 / 倍速読書
  → その日の記録
```

**原則：「今日は何をやればいいのか」をユーザーに考えさせない。**
選ぶのは長さだけで、種目の組み合わせはアプリが決める。
日付と過去の記録から組むので、同じ日なら開き直しても内容は変わらない。
久しく触っていない種目から先に出るため、何週間も出てこない種目ができない。

**どの長さでもサッケイドと倍速読書は必ず入る。**
入口（眼）と出口（実際の読書）を欠くと、その日が何のためだったか分からなくなる。

## 5. 言語方針（日本語ファースト）

- 第一言語は日本語。主要な速度指標は **CPM（Characters Per Minute）**。
- WPM は英語対応時の派生指標として後日追加する（`ReadingSpeedUnit` を型で分離しておく）。
- 日本語特有の要件：文節・意味単位でのチャンク分割、句読点・括弧の扱い、全角文字幅を前提とした組版。

## 6. 主要指標（ユーザーに見せる数値）

**総合点をひとつ出さない。種目ごとの数字を並べる。**
まとめてしまうと、伸びている種目と落ちている種目が打ち消し合って、どちらも見えなくなる。
受講記録がもともとそういう形をしている。

```
たてサッケイド 57 / よこサッケイド 77 / 数字ランダム 22・20・18・24 / ...
```

| 指標 | 定義 | 目的 |
|---|---|---|
| 種目ごとの主スコア | 到達数・正答数・往復数など | その種目の現在地 |
| 級 | 課される制限時間の短さ（種目ごとに独立） | 上達の段 |
| 読書の倍率 | 直近の倍速読書 CPM ÷ 入会時 CPM | **目標は 3 倍** |
| 続けている日数 | 記録が途切れずに続いた日数 | 継続 |

**倍率は倍速読書の記録だけで測る。**
普通読書と混ぜると、速く読もうとした日の数字がふだんの速さとして残り、
伸びたのか、その日がんばっただけなのかが分からなくなる。

**CPM を持つのは読書とベースライン測定だけ。** 他の種目では速度を使わない。

## 7. 級（上達の段）

級とは **課される制限時間の短さ** のことである。
「速く読めたか」で測ると、読んだつもりで飛ばすだけで数字が上がってしまう。
同じ課題を短い時間でこなせるようになったかを見る。

**級は種目ごとに独立している。**
得意な種目に引きずられて苦手な種目まで難しくなる、という事故を起こさない。

課す条件が変わらない種目（カウント呼吸法・かなひろい・読書）は級を持たない。
これらは数字そのものが伸びていくのを見る。

## 8. Gamification 方針

補助的にのみ使用する。実装候補：Streak / XP / Level / Personal Best / Weekly Goal。

- **速度だけを上げるゲームにしない。** 級が上がる条件には、主スコアと正確さの両方を課す種目がある。
  正確さだけを見るとゆっくり確実に拾う人が上がりつづけ、主スコアだけを見ると
  当てずっぽうで数を稼ぐ人が上がってしまう。
- 派手な演出は行わない（集中の妨げになるため）。

## 9. スコープ

**いま入っているもの**

BTR の13種目 / 4段階のセッション（90・45・30・15分）/ 種目ごとの級 /
種目ごとの推移 / Baseline 測定 / 翌日の想起 / 端末内保存・バックアップ・オフライン

**入れないもの**

AI 生成 / SNS / ランキング / 課金 / コミュニティ / PDF Import / Obsidian 連携 /
高度な Gamification

**捨てたもの（Phase 3 の移行で）**

Speed Push / Chunk Reading / Structure Reading / Meaning Flash / Prediction Reading /
Variable Speed / Regression Control / 独立した理解度テスト / Skill Profile（9スキル）。
理由は [BTR_METHOD.md](BTR_METHOD.md) §6。

## 10. Definition of Done

新規ユーザーが、以下をエラーなく一連で完了できること。

1. アプリを開く
2. 入会時の速度を測る（Baseline）
3. 長さを選んでトレーニングを1回通す
4. 種目ごとの記録が残る
5. 推移で「入会時の何倍か」と種目ごとの数字を見る

この一連が Playwright の E2E で自動的に完走することを、機械的な判定基準とする。

## 11. コンテンツ方針

- **著作権上問題のある書籍本文を転載しない。** 教材はすべてこのプロジェクト用のオリジナル日本語文章。
- カテゴリ：Business / Technology / Economics / Psychology / Science / History / General
- Baseline 測定と翌日の想起で使う。BTR の種目の盤面・課題文は日付を種にして生成するか、
  自前で書き起こしたものを使う（教室の教材は使わない）。
- 将来的にユーザー自身の記事・PDF・ノートを教材化できるよう、教材の取り込み口を型で抽象化しておく（MVP では実装しない）。

## 12. デザイン原則

コンセプトは **「集中できる学習ツール」**。派手なゲーム UI にはしない。

- 参考とする方向性：Linear（情報密度と静けさ）、Notion（タイポグラフィ）、Apple Health（指標の見せ方）、Duolingo（進捗設計の考え方のみ）。**いずれも完全コピーはしない。**
- Color：White / Black / Navy / Blue / Gray + アクセント1色
- Typography：本文は十分な行間・読みやすい文字サイズ・distraction-free
- Reading Mode ではナビゲーション等を極力消す
