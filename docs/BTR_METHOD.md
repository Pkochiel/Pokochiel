# BTRメソッドへの移行

このアプリは当初、一般的な「科学的根拠のある速読」の枠組みから独自に設計した。
実際に触ったところ、参考にすべきだったクリエイト速読スクールの **BTRメソッド** とは
別物になっていることが分かったため、全面的に寄せる。この文書はその設計基準である。

## 0. 出典と、この文書の確からしさ

情報源は Web 検索で得られたテキスト（スクール公式サイトの記述、教室ブログに公開されている
受講記録のスコア、書籍紹介ページ）に限られる。**公式サイトと YouTube はこの開発環境の
ネットワークポリシーで直接取得できなかった。**

そのため本文中では、確度を次のように分けて書く。

| 印 | 意味 |
|---|---|
| **[確認]** | 複数の出典で確認できた記述 |
| **[推定]** | 断片から組み立てた推定。実装はするが、実物と違う可能性がある |
| **[未確認]** | 種目名は分かるが中身が取れていない。暫定で作る |

**[推定] / [未確認] は、実際に受講した人・動画を見た人の指摘で上書きすること。**
この文書を「正解」として扱わない。

また、**スクールの教材そのものは使わない。** 訓練の様式（眼球運動、記号の高速走査、
かなひろい等）は一般的な認知訓練の型なので実装するが、シートの中身・課題文はすべて自前で作る。

## 1. BTRメソッドとは

**[確認]** BTR = **Basic Training for Readers**（読書する人のための基礎的訓練）。
読書に必要な情報処理機能（認知機能）を改善するトレーニングシステム。

**[確認]** 柱は2つ。

1. **認知視野の拡大** — 一度に認識できる文字数を増やす
2. **読書内容への集中** — 内容を理解しながら速く処理する

**[確認]** 書籍『速読ジム』の副題は「脳のワーキングメモリを鍛える」。
つまり中核は眼の速さではなく **ワーキングメモリ**。眼は入口にすぎない。

**[確認]** 目標は10倍20倍ではなく **実用的な3倍**。50回の受講で入会時の3倍を保証する制度がある。

### ここが現行アプリと決定的に違う

| | BTRメソッド | 移行前のこのアプリ |
|---|---|---|
| 中心 | **処理速度を上げるドリルの連続** | **読んで設問に答える** |
| 入口 | 文字を介在させない眼球運動 | いきなり意味のある文章 |
| 素材 | 記号・数字・無関連語も大量に使う | 意味のある文章のみ |
| 1回 | 90分・十数種目 | 10〜30分・5〜8ブロック |
| 伸ばし方 | **制限時間を詰めていく** | 目標速度(CPM)を上げる |
| 到達目標 | 実用的な3倍 | 明示なし |

先に受けた「トレーニング間の設問が多い」という指摘は、この構造のズレの症状だった。
設問数を削って対処したが、対症療法にすぎない。設問中心をやめるのが本筋である。

## 2. 1回の構成（4段階）

**[確認]** 1回90分。順序は次のとおり。

```
【1】カウント呼吸法        身体の緊張を解き、集中するための準備
【2】認知視野拡大          サッケイドシート / ランダムシート / パターンシート
                          / ユニットブック / BPシート
【3】読書内容への集中      スピードチェック / かなひろい / ロジカルテスト
                          / スピードボード / イメージボード / イメージ記憶
【4】倍速読書・速読読みきり 実際の書籍を使い、タイムを計測して総仕上げ
```

**[確認]** サッケイドシートは「文字を介在させず眼球運動だけに集中する」もの。
ここが現行アプリに丸ごと欠けている段である。

## 3. 種目一覧

移行後に実装する種目。90分は前提にせず、時間に応じて種目を選ぶのは現行の仕組みを踏襲する。

### 【1】準備

| 種目 | 内容 | 記録 | 確度 |
|---|---|---|---|
| カウント呼吸法 | **制限時間内に自分が何回呼吸したかを数える** | 呼吸数（少ないほうがよい） | **[確認]** |

#### カウント呼吸法 **[確認]**

**制限時間内に自分が何回呼吸したかを数える。**
呼吸を指定の速さに合わせるのではなく、いまの自分の呼吸を測る。

**この種目だけスコアの向きが逆で、少ないほうがよい。**
呼吸が深くゆっくりになるほど回数は減る。他の種目と同じ「多いほど良い」で扱うと
評価が反転するため、`lowerIsBetter` を型に持たせて取り違えを防いでいる。

### 【2】認知視野拡大

| 種目 | 内容 | 記録 | 確度 |
|---|---|---|---|
| たてサッケイド | 上下のマーカー間で視線を往復させる。文字は読まない | **往復数** | **[確認]** |
| よこサッケイド | 左右のマーカー間で視線を往復させる | **往復数** | **[確認]** |
| 数字ランダム（ランダムシート） | **1〜99 が散らばった盤を1から順に拾う。4種類のシート** | 到達数 ×4 | **[確認]** |
| ユニットブック | **よく似た8つの文から、お題の文がどの列にあるか探す** | 正答数 | **[確認]** |
| BPシート | **動きの中で文字を判別する。** ランダムシートの動く版 | 発見数 | [確認]位置づけ / [推定]動きの速さ |
| 漢数字一行 | 一〜十の漢数字を並べた盤から、対象の数字を探す | 発見数 ×3ターン | **[確認]** |

#### サッケイド **[確認]**

スコアは **往復数**。`たてサッケイド 57` は30秒で57往復した、という意味。

**たて・よこの2種類があり、毎回のトレーニングでランダムに切り替わる。**
両方を毎回やるのではない。プラン生成もこれに合わせ、その日どちらか一方だけを出す。

#### 数字ランダム **[確認]**

**1〜99 が画面の中にランダムにちりばめられている。それを1から順に拾う。**
制限時間内にどこまで到達できたかがスコア。**4種類のシート**を使う。
公開スコア `数字ランダム 22・20・18・24` の4つは、この4枚それぞれの到達数である。

盤面を格子で作らず散らすのは、次に拾う数の位置を予測できないようにするため。
整列していると視線が行を走るだけになり、盤面全体を走査する訓練にならない。

#### ユニットブック **[確認]**

縦一行のユニットが **8列**並ぶ。どれもよく似た文で、位置は毎回入れ替わる。
お題の文がどの列にあるかを、どれだけ速く見つけられるかを見る。正解数で級を判定する。

```
おじいさんは山へ芝刈りに行きました。
おばあさんは山へ芝刈りに行きました。
おじいさんは山へ芝刈りに行きません。
おばあさんは山へ芝刈りに行きません。
おじいさんは川へ洗たくに行きました。
おばあさんは川へ洗たくに行きました。
おじいさんは川へ洗たくに行きません。
おばあさんは川へ洗たくに行きません。
```

**8列は3つの二択の総当たり**である（だれが／どこへ・なにを／したかどうか）。
どの2列も1〜3か所しか違わないので、拾い読みでは当たらない。
文の頭だけ見て決めると外れるところがこの種目の要点である。

#### BPシート [確認]位置づけ / [推定]中身

**動きの中で文字を判別する。** シート訓練は次の順に難しくなる。

```
ページ全体から文字を判別（ランダムシート）
→ 動きの中で文字を判別（BPシート）
→ 動きの中で文章を判別（たて一行ユニット ＝ ユニットブック）
```

つまり BPシートは数字ランダムの「動く版」、ユニットブックはさらにその「文章版」にあたる。
この階梯が分かったので、3つを別々の課題ではなく **同じ軸の3段** として実装する。

「BP」が何の略かは分からなかった。動きの速さ・出し方も推定である。
実装では、文字が次々に現れて一定時間で消える形にし、消える前に対象を拾わせている。
級が上がるほど滞留時間が短くなる。

#### 漢数字一行 **[確認]**

盤面は **一〜十の漢数字**で埋まっている。横に30、縦に3。
**「一を探すターン」「二を探すターン」「三を探すターン」があり、各90秒。**
その盤から対象の漢数字だけを拾い出す選択的注意の課題である。

### 【3】読書内容への集中

| 種目 | 内容 | 記録 | 確度 |
|---|---|---|---|
| スピードチェック | **方角漢字の組み合わせ**の中から、対象の組み合わせを探す | 発見数 / 所要時間 | **[確認]** |
| かなひろい | 物語文を読みながら「あ・い・う・え・お」に印をつけ、**終了後に内容を確認** | 拾い数 / 見落とし / 内容正答 | **[確認]** 手順まで確認済み（後述） |
| ロジカルテスト | 順序関係と三段論法を高速で判定する | 正答数 / 所要時間 | **[確認]** |
| スピードボード | **5×5 の盤。真ん中からの移動指示の行き先を指す** | 正答数 | **[確認]** |
| イメージ記憶（イメージボード） | **40語を制限時間で覚え、再生する。同じ語で2セット** | 再生数 ×2セット | **[確認]** |

#### スピードチェック **[確認]**

盤面は **方角漢字（東・西・南・北）の2文字の組み合わせ**で埋まっている。
その中から指定された組み合わせ（たとえば「南東」）を探し出す。
似た字面が大量に並ぶため、字形ではなく組み合わせとして掴む必要がある。

#### かなひろい **[確認]**

一般に「かなひろいテスト」として知られる選択的抹消課題。主命題（物語の理解）を維持したまま
注意を分散させる二重課題である。手順：

1. 「次の文の中から、あ・い・う・え・お をひろいあげて○をつけてください。
   なるべく速く、見落とさないように、**物語の内容も考えながら**行ってください」
2. 2分で終了
3. **その後、内容を把握しているか確認して正答数を算出する**

**この種目が、我々が求めていた「理解の測定」を自然に内包している。**
別ブロックとして設問を並べる必要はない。読みながら拾い、あとで内容を訊く。それで足りる。

#### ロジカルテスト **[確認]**

30問・制限時間つき。出題は **順序関係の推論と三段論法の両方**。

```
順序関係  「A は B より背が高い」「B は C より背が高い」→「A は C より背が高い」
三段論法  「すべての A は B」「すべての B は C」→「すべての A は C」
```

**前提がつながらない出題を必ず混ぜる。**
「A は B より背が高い」「C は D より背が低い」から A と C の関係は決まらない。
ここで「判断できない」を選べるかがこの種目の核心なので、答えは
**正しい / 誤り / 判断できない** の3択にする。2択だと当てずっぽうで半分当たってしまう。

問題は種から機械生成する。同じ日なら同じ出題、翌日は別の出題になる。

#### スピードボード **[確認]**

**5×5 の盤。真ん中の点からどう動くかの指示が書いてあり、その指示の場所をどれだけ速く指せるか。**
正解数で級を判定する。

盤の上で指を滑らせて数えるのではなく、頭の中で位置を動かすのが要点。
指示は「右に2、上に1」のように複数の手を含み、級が上がるほど手数が増える。
盤の外へ出る指示は作らない（「盤の外だから答えられない」は測りたいものではない）。
同じ向きを続けない（「右に1、右に1」は「右に2」と同じで手数が水増しになる）。

#### イメージ記憶（イメージボード） **[確認]**

**40個の単語を2分で覚え、思い出せたものを答える。同じ単語で2セット行う。**
級が上がるごとに制限時間が短くなる：**2分 → 1分30秒 → 1分 → 45秒 → 30秒**（40語中36語で次の段へ）。

単語は上下に並べて出す。上下2語を結ぶ具体的なイメージを作って覚えるのがこつで、
強く印象的なイメージほど残る。

スクールの案内では「イメージボード」と「イメージ記憶」が別の名前で挙がっているが、
受講した人の話では **同じ語彙を使う同じ訓練** とのことなので、ひとつの種目として実装する。
別物だと分かったら分ける。

主スコアは **2セットのうち良いほう**。合計にすると同じ語を2回数えることになり、
覚えられた語数を表さない。あわせて「2セットのどちらかで拾えた語の数」も記録し、
1セット目の取りこぼしを2セット目で回収できたかを見る。

これは BTR 全体のレベル進行の型である（次節）。

### 【4】仕上げ

| 種目 | 内容 | 記録 | 確度 |
|---|---|---|---|
| 倍速読書 | **自分の本**を読み、読んだページ数と時間を記録する | ページ数 / 分速 | **[確認]** |
| 速読読みきり | 一冊を読み切る | [未確認] | [確認]名称のみ |

#### 倍速読書 **[確認]**

**自分の本**を読み、**読んだページ数**と時間を記録する。
用意された教材ではなく実際の本を使うのがこの種目の要点である。

本を登録するときに **1ページあたりの文字数** を入れてもらい、ページ数から字数を出す。
本が変わったら、本の名前と一緒に登録し直す。

```
字数 ＝ ページ数 × 1ページの文字数
分速 ＝ 字数 ÷ 分
倍率 ＝ 分速 ÷ Baseline の分速     ← 目標は3倍
```

**ここと Baseline 測定だけが CPM を持つ。** 他の種目では速度を使わない。

## 4. レベル進行：制限時間を詰める

**[確認]** イメージ記憶の例：2分 → 1分30秒 → 1分 → 45秒 → 30秒。
基準スコア（36点）を超えたら次の段へ。

現行アプリは「理解度が保てていれば目標CPMを上げる」方式だった。これを次に差し替える。

```
種目ごとに      基準スコア と 制限時間の段階列 を持つ
基準を超えた    → 次に短い制限時間へ
基準を割った    → ひとつ前の制限時間へ戻す
```

速度そのものではなく **同じ課題を短い時間でこなせるか** を進捗の定義にする。
これは「速く読めたか」より測りやすく、ごまかしが効かない。

**級は種目ごとに独立している。** 全体でひとつの級を持つのではなく、
サッケイドの級、ロジカルテストの級、イメージ記憶の級をそれぞれ別に上下させる。
得意な種目に引きずられて苦手な種目まで難しくなる、という事故が起きない。

例外はカウント呼吸法。これは訓練ではなく状態の測定なので級を持たない。

## 4-b. 1回90分の配分（案）

教室の実際の配分は未確認。次は **こちらからの提案** であり、確認が取れたら差し替える。

配分の考え方は3つ。

1. **眼から入って頭で終える。** 準備 → 眼の運動 → 走査 → 処理 → 記憶 → 実際の読書。
   疲れが出る前に負荷の高いものを置き、最後は実際の本を読んで締める
2. **各種目の制限時間は仕様で決まっている。**（漢数字一行は3ターン×90秒＝4分30秒、
   イメージ記憶は2セット×2分＝4分など）配分はそれに切り替えと説明の時間を足したもの
3. **毎回すべてはやらない。** サッケイドはたて・よこのどちらか。
   処理系も日替わりで回し、1回に詰め込みすぎない

| | 種目 | 分 | 内訳 |
|---|---|---|---|
| 【1】 | カウント呼吸法 | 3 | 準備 |
| 【2】 | サッケイド（たて or よこ） | 5 | 30秒×数本＋切り替え |
| | 数字ランダム | 6 | 4枚×60秒＋切り替え |
| | ユニットブック | 6 | 20問 |
| | 漢数字一行 | 6 | 3ターン×90秒 |
| 【3】 | スピードチェック | 6 | |
| | かなひろい | 8 | 2分の抹消＋内容確認 |
| | ロジカルテスト | 8 | 30問 |
| | スピードボード | 8 | 30問 |
| | イメージ記憶 | 10 | 2セット×2分＋再生 |
| 【4】 | 倍速読書 | 20 | 実際の本 |
| | 記録と振り返り | 4 | スコアの確認 |
| | **合計** | **90** | |

短い時間のときは、この並びから前から詰める。

| 時間 | 構成 |
|---|---|
| 90分 | 上の全体 |
| 45分 | 呼吸3 + サッケイド5 + 認知視野から2種目12 + 処理系から2種目14 + 倍速読書10 + 記録1 |
| 30分 | 呼吸2 + サッケイド4 + 認知視野から1種目6 + 処理系から1種目8 + 倍速読書9 + 記録1 |
| 15分 | 呼吸1 + サッケイド4 + 認知視野から1種目5 + 倍速読書5 |

**どの長さでもサッケイドと倍速読書は必ず入れる。**
入口（眼）と出口（実際の読書）を欠くと、その日のトレーニングが何のためだったか分からなくなる。
処理系と記憶系は日替わりで回す。

## 5. スコアの型

**[確認]** 受講記録は種目ごとの数値の並びで、回ごとに記録して推移を見る形式。

```
たてサッケイド 57 / よこサッケイド 77 / 数字ランダム 22・20・18・24 / ...
```

移行後の `TrainingResult` はこれに合わせる。

| 列 | 意味 |
|---|---|
| `trainingType` | 種目 |
| `score` | その種目の主スコア（到達数・正答数・往復数） |
| `attempts` | 複数試行する種目の各試行スコア（数字ランダムなど） |
| `elapsedMs` | 所要時間（時間制のものは制限時間そのもの） |
| `timeLimitMs` | そのとき課された制限時間（レベルに相当） |
| `accuracy` | 見落とし率など、質を表す副指標 |

**CPM は倍速読書とベースライン測定にだけ残す。** 他の種目では使わない。

## 6. 移行で捨てるもの

現行の以下は BTR に対応する種目がない。撤去する。

- `chunk_reading`（チャンク表示）— 認知視野拡大の思想は継ぐが、実装形態はサッケイド／ランダムシートへ
- `meaning_flash` — イメージ記憶に置き換え
- `structure_reading` — かなひろいの内容確認へ統合
- `prediction_reading` — BTR に対応なし
- `variable_speed` — BTR に対応なし
- `regression_control` — BTR に対応なし
- `comprehension`（独立した設問ブロック）— かなひろい／ロジカルテストへ統合
- `speed_push` — 倍速読書へ

残すもの：

- Baseline 測定（入会時の速度。**3倍**の分母になるので必須）
- 翌日 Recall（BTR に明示的な対応はないが、記憶の定着を見る指標として維持する。
  ただし主役ではなく補助に降ろす）
- 保存・バックアップ・オフライン（Phase 2 の基盤はそのまま使える）

## 8. 紙とアプリで変えざるを得ないところ

### サッケイドの計測

教室では紙のシートを見て **自分で往復数を数える**。アプリで自己申告にすると数字だけが
上がって訓練にならないため、次の形に置き換える。

```
上下（左右）のマーカーが交互に点灯する
点灯した側をキー／タップで答える
30秒で正しく答えられた回数 ＝ 往復数
点灯の間隔はレベルで詰めていく（§4 の時間短縮方式）
```

点灯側を知るには視線を動かすほかないので、眼球運動は実際に起きる。
**文字を介在させない**という原則も守れる。ただし「往復数」の絶対値は
教室のスコアとは直接比較できない。比較するのは自分の推移だけにする。

### 盤面の中身

数字ランダム・漢数字一行・スピードチェックの盤面は、日付を種にした擬似乱数で生成する。
同じ日なら同じ盤面、翌日は別の盤面になる。教室の教材は使わない。
