# TEST - YouTube - 生成AIエージェントが企業業務をどう変えるか

## メモ（視聴しながらの書き起こし・要約混在）

[03:20] これまでの生成AI活用は「チャットで聞く」に留まっていた。次の段階は
**Agentic AI**、つまりAIが自分で計画を立て、ツールを呼び、結果を検証して
やり直すループを回すこと。人間が毎回プロンプトを打つのではなく、
ゴールだけ与える形に変わる。

[08:45] エージェントの実力は「推論モデルの賢さ」より**外部データへのアクセス品質**で
決まる。RAG がその中核。ただし RAG は万能ではなく、検索が悪ければ
どれだけモデルが賢くても出力は良くならない。登壇者いわく
「RAGの上限は検索の質で決まる。生成側をいくら強化しても検索が悪ければ無駄」。

[15:10] ツール接続の標準化として **MCP**（Model Context Protocol）が普及しはじめた。
これまで各社が独自にコネクタを書いていたが、MCPにより
「1回書けばどのモデルからも使える」形になる。企業の社内システム連携コストが
大きく下がる。

[22:30] 業務自動化の実例。経費精算、問い合わせ一次対応、契約書レビューの下読み、
定型レポート生成。共通しているのは「判断の幅が狭く、正解の定義が明確な業務」。
逆に、判断基準が曖昧な業務にエージェントを入れると事故る。

[31:00] **Human-in-the-loop** の設計が本番導入の分かれ目。
全自動にすると、精度95%でも残り5%の事故が信頼を破壊する。
重要なのは「どこで人間に承認を求めるか」の設計。
承認ポイントが多すぎると自動化の意味がなくなり、少なすぎると事故る。
登壇者の主張：「エージェント導入の設計とは、自動化する範囲の設計ではなく、
**人間が介入する点の設計**である」。

[38:40] 組織的な話。エージェント導入で最初に効くのは人員削減ではなく
「これまで人手が足りずやっていなかった業務が回り始めること」。
ROIを人件費削減だけで測ると失敗する。
